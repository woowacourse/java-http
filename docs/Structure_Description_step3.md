## 프로젝트 구조 정리

### 전체적인 Http11Processor의 요청 처리 흐름

- Http11Processor에서 요청과 응답 객체를 생성해서 FrontController에 전달
- FrontController 동작
    - 요청을 처리가능한 컨트롤러를 찾음
    - 찾은 컨트롤러에서 요청을 처리하고 응답을 생성
    - 만약 예외가 발생하면 예외응답 처리
- Http11Processor에서 응답 객체를 통해 클라이언트에게 응답 전송

### FrontController 도입 이유

- Http11Processor는 요청마다 생성되는 스레드인데 현재 웹서버에 있는 모든 컨트롤러를 필드로 갖고 있는 것이 적절하지 않다고 느낌
- Http11Processor에서 요청을 처리한 컨트롤러를 찾고, 컨트롤러를 실행하고, 예외응답 처리까지 수행하기에는 책임이 너무 많다고 느낌
- 결과적으로 컨트롤러들을 관리하는 최상단 컨트롤러인 프런트 컨트롤러를 도입하게 되었습니다!

### 테스트가 통과하지 않는 이유

- 헤더의 대소문자
    - HTTP 명세에 따르면 헤더의 대소문자 구분이 없다고 합니다!
    - 하지만 테스트에서는 이를 허용하지 않기에 테스트가 실패합니다!
    - (실제 API 요청은 정상적으로 동작합니다!)

- 헤더 라인 끝의 공백
    - HTTP 명세에 따르면 헤더 라인마다의 끝에 공백을 붙이지 않는다고 합니다!
    - 하지만 테스트에서는 모두 공백을 추가하고 있어 테스트가 실패합니다!
    - (실제 API 요청은 정상적으로 동작합니다!)

- 위와 같은 이유로 현재 테스트가 통과하지 않아도 문제가 없다고 판단했습니다!
